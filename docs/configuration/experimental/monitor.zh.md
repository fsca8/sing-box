!!! question "自 sing-box 1.8.0 起（monitor：仅本分支）"

### 结构

```json
{
  "max_dns_rows": 2000,
  "max_conn_rows": 1000,
  "fail_dedupe_sec": 60
}
```

### 字段

所有字段均为可选：`0` 使用默认值，正数表示覆盖默认值。

记录**只留在内存里**——两个定容环形缓冲，没有数据库文件。磁盘上不写任何监控数据，
进程重启后历史即清空。环写满后覆盖最旧的记录，被覆盖的条数由 `/monitor/stats` 与
`/monitor/health` 的 `dropped` 字段给出。

客户端单次最多读取 1000 条，所以环容量决定的是「最新的记录能倒推到多久以前」，
而不是"一共有多少条"。

#### max_dns_rows

内存中保留的 DNS 记录条数。默认 `2000`。`0` 与负数都使用默认值（环形缓冲必须有界）；
大于 `50000` 的值会被截断为 `50000`。

#### max_conn_rows

内存中保留的连接记录条数。默认 `1000`。`0` 与负数都使用默认值；大于 `20000` 的值会被
截断为 `20000`。

#### fail_dedupe_sec

失败记录的合并窗口：窗口内对同一目的地（连接侧看 `remote` + `outbound`，DNS 侧看
`domain` + `qtype` + `status`）的重复失败只记录第一条。

一次上游故障会产生成片的失败记录，正是它们把有用的历史挤出环外。默认 `60` 秒，
负数表示关闭去重。

#### 已停用字段

`max_size_mb`、`retention_days`、`maintenance_log_sec` 是落库时代的配置项。它们仍然被接受
（旧配置因此可以继续使用），但已经不再有任何效果。
